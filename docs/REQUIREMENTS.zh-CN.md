# 开发任务：Visual Document Capture —— 基于计算机视觉的文档采集与 PDF 重建软件

## 一、项目背景与总体目标

请开发一款适用于 **Windows 11** 的轻量级桌面软件，暂定名为 **Visual Document Capture（VDC）**。

主要使用场景：

用户通过 Chrome、Edge 等浏览器查看在线 PDF、学术论文、电子书或者各类在线文献阅读器。这些文档可以通过鼠标滚轮连续上下滚动，但未必能够直接下载原始 PDF。

我希望软件能够：

1. 启动后允许用户用鼠标框选屏幕上的任意矩形区域。
2. 用户在选定区域内正常滚动文档时，软件自动采集屏幕图像。
3. 通过计算机视觉识别相邻截图的重叠部分，恢复连续文档。
4. 自动识别原始纸张边缘、页面上下边界及分页间隔。
5. 将连续内容正确切分为多个独立页面，输出多页 PDF。
6. 后续支持自动滚动、自动完成采集、后台运行等功能。

### 最重要的设计约束

本软件必须坚持 **视觉优先、与目标应用解耦**：

- 不读取网页 DOM、HTML、CSS 或浏览器内部的页面结构。
- 不依赖 PDF.js API、PDF 页码接口、Canvas 内部数据或原始 PDF 文件。
- 不通过网络请求获取文档原始资源。
- 不要求特定浏览器或网站提供专用接口。
- 只利用用户指定区域中的可见像素信息完成采集、拼接与分页。
- OCR 可以作为后续扩展，但不能成为基础分页算法的必要条件。
- 所有截图和生成文件默认只在本地处理，不上传云端。
- 不实现绕过登录、付费权限或访问控制的功能。

后续允许使用 Windows 图形采集 API、窗口定位 API 和输入自动化 API，但不得改变“文档内容识别完全依赖视觉”的原则。

**特别注意：本项目不是普通长截图软件，而是能够尽可能准确恢复原始文档分页结构的软件。**

## 二、开发技术栈

优先使用 Python，保证代码可维护、易于调试。

建议：

- Python 3.12+
- PySide6：GUI、区域选择器、悬浮工具栏、分页预览。
- MSS：初期屏幕区域截图。
- NumPy：像素分析。
- OpenCV：图像配准、重叠检测、纸张边缘识别、分页检测。
- PyMuPDF：PDF 输出、页面尺寸设置、图像嵌入。
- Pillow：必要的图像处理。
- pytest：自动化测试。
- PyInstaller：最终打包为 Windows 可执行程序。

后续可根据需要加入：

- Windows Graphics Capture / DXGI Desktop Duplication。
- Windows UI Automation、pywin32 或其他合适的输入自动化组件。
- Tesseract / PaddleOCR：可选 OCR 功能。

不需要拘泥于这些依赖。如果存在明显更可靠、更成熟的技术方案，可以调整，但必须解释原因。

### 架构要求

请采用模块化设计，至少划分：

```text
visual-document-capture/
├── src/
│   └── vdc/

│       ├── export/        # PDF 导出
│       ├── automation/    # 自动滚动与后台运行
│       └── utils/         # 日志、配置、通用工具
├── tests/
│   ├── fixtures/
│   ├── unit/
│   └── integration/
├── examples/
├── docs/
```

目录可以按实际需要调整，但核心算法不得和 GUI 代码混在一起。

所有算法必须能够在不启动 GUI 的条件下独立测试。

# 三、工程阶段划分

## Phase 0：技术验证与测试基础

目标：优先验证最关键的两个技术问题：

1. 能否仅凭连续截图准确恢复滚动文档？
2. 能否仅凭视觉信息恢复原始分页？

### 任务 0.1：构造测试数据

生成一组虚拟 PDF 文档及其对应的模拟阅读器截图。

测试文档应包含：

- 单栏文字。
- 双栏论文。
- 数学公式。
- 图片、表格。
- 不同长度的空白区域。
- 页眉、页脚、页码。
- 不同页面尺寸。
- 白色页面与灰色背景。
- 页间存在 5–30 像素左右的间隔。
- 连续滚动时任意两页可能同时显示在截图中。

根据这些文档模拟不同滚动速度下的截图序列。

保留真实的页面边界、滚动位移、页数与原始图像作为 Ground Truth。

### 任务 0.2：图像拼接原型

输入：连续滚动截图序列。

输出：重建的连续文档图像，或等价的分段图像表示。

至少实现：

- 相邻截图的纵向位移估计。
- 图像重叠区域识别。
- 重复像素区域去除。
- 拼接置信度估计。
- 滚动过快导致无重叠时的识别。
- 静止画面和反向滚动的处理。
- 匹配失败时的错误报告。

可以比较：

- Template Matching。
- Phase Correlation。
- 特征点配准。
- 基于文本边缘的纵向匹配。

选择适合文档图像的方案，不必局限于单一算法。

特别考虑大量白色区域、重复行距、相似段落造成的错误匹配。

### 任务 0.3：分页检测原型

只使用截图像素，检测：

- 纸张左右边界。
- 纸张顶部、底部。
- 页面之间的背景间隔。
- 页面宽度和高度的一致性。
- 页面尺寸或纵横比的变化。

不能简单地将水平空白视为分页，因为论文内部也存在空白区域。

应结合纸张轮廓、背景特征、跨帧一致性和页面几何信息判断。

每个检测结果必须包含置信度。

对于无法从视觉确定的分页，不允许假装检测成功。

### Phase 0 验收

必须完成：

- 可重复运行的测试脚本。
- Ground Truth 与检测结果的定量比较。
- 拼接错误、分页遗漏、错误分页的统计。
- 主要失败案例及原因分析。
- 一份技术验证报告。

不要只展示成功样例；必须包含失败和边界情况。

## Phase 1：基础 GUI + 手动滚动采集 + 多页 PDF（MVP）

这是第一版正式软件，也是当前最重要的开发阶段。

### 任务 1.1：区域框选

软件启动后提供：

- 新建采集任务。
- 全屏半透明选区界面。
- 鼠标拖动框选矩形区域。
- 可调整选区边界。
- 记录区域屏幕坐标。
- 支持 Windows 多显示器。
- 正确处理不同 DPI 缩放比例。

选区应当允许包含纸张外部背景和页间空隙。

框选完成后，选区提示应自动隐藏，不能污染截图。

### 任务 1.2：手动滚动时自动采集

用户点击“开始采集”后：

- 软件持续监控指定屏幕区域。
- 用户正常操作鼠标滚轮。
- 软件根据画面变化判断是否需要采集新帧。
- 自动忽略静止或重复画面。
- 将截图送入拼接队列。
- 显示已采集内容、当前状态和错误提示。

采集应基于独立工作线程或异步任务，不得阻塞 GUI。

建议根据画面变化自适应截图频率，而不是无条件保存大量重复截图。

需要支持：

- 开始。
- 暂停。
- 恢复。
- 结束。
- 取消。
- 错误恢复。

快捷键可以后续配置。

### 任务 1.3：可靠的滚动拼接

这是最关键的核心模块。

要求：

1. 估计前后两次有效截图的滚动位移。
2. 找出有效重叠区域。
3. 只追加新增内容。
4. 识别正向滚动、反向滚动和静止。
5. 滚动回到已采集位置时避免重复追加。
6. 匹配失败时停止错误传播。
7. 保留可供诊断的匹配置信度和失败信息。

还需要处理：

- 鼠标指针偶尔进入截图区域。
- 浏览器固定工具栏。
- 滚动条。
- 浮动按钮。
- 动态加载。
- 渲染尚未完成。
- 页面缩放变化。
- 大块空白区域。

建议允许用户指定或自动检测有效内容子区域，尽量排除固定 UI 对拼接的干扰。

对滚动速度过快造成的内容遗漏，必须提示用户返回该区域重新采集。

**不得在拼接失败后直接以猜测位移的方式继续输出看似完整的文档。**

### 任务 1.4：自动分页识别

将 Phase 0 验证过的分页算法集成到实时采集中。

识别目标：

- 每张纸张的左右边界。
- 每张纸张的顶部和底部。
- 两页之间的间隔。
- 页面纵横比。
- 可能存在的不同尺寸页面。

优先采用：

纸张边界 + 页间背景 + 多页几何一致性 + 跨帧观察。

分页检测应尽量利用连续截图中的原始信息，不局限于最终拼接图。

需要记录：

- Page ID。
- 页面在重建文档中的位置。
- 页面边界。
- 页面置信度。
- 页面是否完整。
- 是否存在缺失区域。

对于从中间开始或提前结束的采集，必须将首尾不完整页面标记出来。

### 任务 1.5：分页预览与人工校正

设计简单直观的页面编辑器。

左侧：已识别页面的缩略图列表。

右侧：选中页面的大图预览。

支持：

- 查看自动分页结果。
- 调整页面顶部和底部边界。
- 调整左右裁剪边界。
- 将两段内容合并为一页。
- 将错误合并的内容拆分为两页。
- 删除错误页。
- 标识未完整采集的页面。
- 重新采集问题区域。

自动识别无法确定的分页应高亮提示。

不需要实现复杂的 PDF 编辑器，只需要完成分页修正。

### 任务 1.6：PDF 导出

最终输出必须是真正的多页 PDF。

要求：

- 每张识别出的原始页面对应一个 PDF 页面。
- 正确保留页面顺序。
- 尽量保留原始页面纵横比。
- 不强制所有页面设为 A4。
- 避免无意义的图像缩放和二次压缩。
- 可以设置输出路径、文件名与图像压缩质量。
- 导出前提示缺页、重复页、不完整页和低置信度分页。

需要说明：截图无法保证恢复原始 PDF 的矢量信息或实际分辨率。

优先保证图像清晰、分页正确和文档完整。

### 任务 1.7：会话持久化

不能把全部截图直接拼成一张无限增长的大图片。

应该：

- 将截图块和中间结果保存至磁盘。
- 控制内存使用。
- 记录采集过程和拼接状态。
- 支持重新打开未完成任务。
- 在软件异常退出后尽量恢复已有成果。
- 导出成功后允许用户选择清理临时文件。

### Phase 1 验收标准

在 Windows 11 的 Chrome / Edge 阅读器中：

1. 用户能够框选任意文档显示区域。
2. 手动滚动不少于 20 页的测试 PDF。
3. 软件自动恢复连续内容并检测分页。
4. 对所有检测失败和缺失内容进行明确提示。
5. 能在预览中修正分页。
6. 最终输出可正常打开的多页 PDF。
7. 对照已知原始文档，检查页面顺序、缺失、重复及裁切。
8. 软件不会因 20 页以上文档的拼接而出现明显内存失控。

**MVP 的目标不是追求所有场景 100% 自动识别，而是保证错误可发现、可修正，最终能可靠导出。**

## Phase 2：自动滚动、自动截图、自动完成任务

在 Phase 1 稳定后开发。

目标：用户框选区域并点击开始后，不再需要手动滚动。

### 任务 2.1：自动滚动

通过 Windows 输入自动化控制目标区域滚动。

支持：

- 设置滚动步长。
- 设置滚动速度。
- 设置截图间隔。
- 自动等待画面稳定。
- 自动调整滚动步长。

初期要求文档窗口处于前台，允许自动化使用鼠标输入。

### 任务 2.2：闭环控制

不要简单地每隔固定时间滚动一次。

应该使用：

滚动 → 等待稳定 → 截图 → 匹配 → 判断是否完整 → 继续滚动。

每次滚动必须保留足够重叠区域。

如果发现没有足够重叠：

- 尝试小幅回滚。
- 重新采集。
- 降低滚动步长。
- 重试达到次数上限后暂停并报告。

### 任务 2.3：自动检测文档结束

可以综合使用：

- 滚动命令后画面不再变化。
- 连续多次出现相同底部画面。
- 页面下边界已经被检测到。
- 已采集内容覆盖到最后一页底部。

必须防止将网络加载延迟误判为文档结束。

允许用户手动指定结束。

### 任务 2.4：一键采集流程

用户操作：

1. 框选区域。
2. 将阅读器滚动至第一页。
3. 点击“自动采集”。
4. 软件自动滚动、拼接、识别分页。
5. 自动生成分页预览。
6. 用户确认后导出 PDF。

### Phase 2 验收

针对已知页数的测试 PDF，能够从第一页开始自动采集到最后一页，中间不需要人工滚动，并对失败区域提供可恢复的处理机制。

## Phase 3：多显示器、非活动窗口与后台采集

这是高级功能，不得以破坏前两阶段稳定性为代价。

目标：用户将文献阅读器放在副显示器，软件自动采集，同时用户继续在主显示器工作。

需要区分以下三种情况：

### Level A：副显示器可见窗口

目标文档在副显示器保持显示。

要求：

- 按选定显示器坐标进行采集。
- 不影响主显示器上的键盘、鼠标操作。
- 尽量避免目标阅读器窗口获取焦点。
- 自动截图和拼接可持续运行。

### Level B：非活动窗口

目标窗口存在但不是当前活动窗口。

研究：

- Windows Graphics Capture。
- Window Capture。
- UI Automation。
- 窗口级输入消息。
- 其他不会抢夺全局鼠标焦点的方法。

允许针对 Chrome / Edge 做专门兼容优化，但不能读取网页结构或者原始文档内容。

如果后台滚动输入不被目标应用支持，必须明确报告，不得虚假宣称采集成功。

### Level C：被遮挡或最小化窗口

作为实验性功能研究。

需要明确：

- 被遮挡窗口是否能正确采集。
- 最小化窗口是否仍然渲染。
- 浏览器是否限制后台定时器、动画或页面绘制。
- 能否通过窗口级截图获得有效画面。

不能假设 Windows 图形 API 一定能够采集最小化窗口。

如果做不到，请提供技术限制说明及降级方案。

### Phase 3 验收

至少实现在副显示器上对文档进行自动采集，而主显示器可以进行一般工作，且不会持续抢夺用户的鼠标指针或输入焦点。

非活动窗口与最小化窗口功能按照实测兼容性单独记录。

# 四、工程质量与测试要求

整个开发过程必须遵守：

### 1. 可靠性高于表面成功率

宁可提示某一段无法确认，也不能悄悄遗漏正文、重复段落或者产生错误分页。

### 2. 算法与 GUI 解耦

所有核心算法都必须有明确输入和输出。

例如：

- estimate_scroll_offset()
- validate_frame_alignment()
- stitch_document_segment()
- detect_page_boundaries()
- reconstruct_pages()
- export_multipage_pdf()

函数名可调整，但需要明确模块职责。

### 3. 定量验证

通过测试数据和 Ground Truth 测量：

- 滚动位移误差。
- 拼接正确率。
- 漏采区域。
- 重复区域。
- 分页检测精确率和召回率。
- 完整页识别率。
- PDF 页面数与页序正确性。
- 内存占用和处理时间。

区分：

- 检测正确。
- 检测失败但成功报警。
- 检测失败且未报警。

第三类错误尤其需要控制。

### 4. 实际使用反馈

- 当前采集状态。

### 5. 日志与调试

可以保存必要的中间截图、匹配位置、分页候选点和置信度。

普通模式避免大量日志和不必要的磁盘占用。

### 6. 错误处理

必须处理：

- 截图权限或采集失败。
- 窗口被关闭。
- 用户改变缩放。
- 区域坐标变化。
- 图片匹配失败。
- 磁盘空间不足。
- PDF 导出失败。
- 用户中途停止。
- 软件异常退出。
